# ADR 0005: M2 requirements ownership and development human review

Status: implemented candidate for human review; no production approval.

Project Service owns structured requirements, durable sessions/operations, append-only revisions and approval records in PostgreSQL. Agent Service executes a bounded LangGraph prepare → Gateway → validate/retry graph. Project Service persists validated output and graph execution metadata; the Agent Service has no database, provider SDK, tools or approval endpoint. Interrupted operations are marked failed at single-replica startup and require explicit user retry. A PostgreSQL lifetime advisory lock refuses a second live replica before recovery. No automatic regeneration after restart and no claim of mid-token resume or multi-replica coordination.

All saved revisions and decision history are append-only, enforced by PostgreSQL triggers plus ORM guards. A human decision binds project/session, exact revision, canonical SHA-256 content hash, decision, scope, identity and timestamp. The session lock and optimistic version prevent stale or concurrent changes. Approved baseline pointers survive new drafts. Each mutation uses a project/session-scoped idempotency key and request hash; completed results replay and changed payloads conflict. Streaming emits progress and a saved acknowledgement only after validation and commit; raw unvalidated PRD tokens are not rendered.

M1 remains backward-compatible and retains its server-selected developer identity. M2 routes additionally require a password-verified human identity whose ID matches the project owner, with separate reviewer permission for decisions. Password verifiers use per-account random salts and scrypt; random session tokens are stored only as SHA-256 digests in PostgreSQL and expire in 30 minutes. HttpOnly SameSite=Strict cookies, a non-simple request header and origin checks protect mutations. Logout revokes the server record. Service bearer credentials cannot log in or approve. No shared browser header is accepted as proof of human identity.

This is an explicitly limited, loopback-only development mode. Human authentication refuses non-loopback HTTP and sets Secure on HTTPS cookies. Cookies lack Secure solely on loopback HTTP. The Studio requires the same-origin proxy; cross-origin human cookies are deliberately unsupported. Production startup remains refused; enterprise identity, TLS deployment, MFA and membership administration are outside this development implementation. Do not publish these services or treat the generated acceptance account as production authorization. Account provisioning and local secrets remain outside Git. No roles or repository permissions were changed.

Contracts 0.3.0 are additive candidates; 0.1.0 and 0.2.0 files remain unchanged. Consumers vendor snapshots and build independently. Canonical typed JSON renders Markdown one-way; arbitrary Markdown import is not supported. Deterministic fixtures are labeled test/structured, gated by the existing test-provider setting, and make no live model-quality claim. Commercial/local providers still route exclusively through Gateway with bounded validated parsing; no provider fallback.

The M2 Compose profile is optional. Authorized local acceptance uses project masd-m2, separate database volume and ports 4400/8200/5434. Existing M0/M1 services and data are preserved. Human product-owner authors may approve their saved revisions when permitted; M2 forbids agent self-approval and does not introduce a second-human requirement. Additive migrations preserve history; roll back code while retaining schema/data instead of destructive downgrade. Legacy per-message metadata that was never stored is not fabricated. All PR merges and final milestone acceptance remain human decisions; M3 is not started.
