# M1 design

Approved scope extends the independent-repository baseline: Project Service owns projects and persisted conversations in PostgreSQL; the new LiteLLM gateway owns provider/model routing and never accesses those tables. Angular calls only Project Service. The latter authorizes each project/conversation and transfers bounded context to the private gateway using a backend-only bearer credential and explicit project/user/request IDs.

Local identity is a server-configured user identifier, not a browser-controlled impersonation header. Multiple authenticated production users are out of scope; production startup with this local identity is refused. Integration tests use distinct configured local identities against the same database. Models allowed for a project are pinned in its settings; switching to a new provider requires explicitly saving the project's allowed model choices. No automatic cross-provider fallback occurs.

SQLAlchemy 2 and Alembic manage the Project Service schema. UUID public identifiers never replace owner/project predicates. Archived projects retain conversation records and are read-only. Transactional turn records reserve an idempotency key and persist one user/assistant pair; concurrent active submissions conflict. Reusing a key returns the stored outcome without rerunning a provider. Partial/cancelled/interrupted results remain distinguishable; retries use a new key only after terminal reconciliation. Startup marks interrupted generation records failed; no resume-from-token capability is advertised. Deploy one Project Service replica for M1 local development.

SSE emits start, delta, done and error events. Cancellation closes the provider stream and records a cancelled result; an explicit cancellation endpoint also supports an active stream. Completion persistence precedes the done event. Disconnect/cancellation and network failures leave recoverable persisted outcomes. Context uses a configurable conservative byte/token budget and deterministic newest-complete-message selection; no unlimited history, RAG or summarization. Usage/cost stay null unless provider/pricing data exists; test responses are explicitly labeled deterministic and never called commercial output.

All remote calls have timeouts, models are catalog-selected, gateway requests require backend credentials and bounded validated fields. Logs contain correlation IDs and execution metadata, never prompt text or keys. Safe Markdown is parsed and Angular-sanitized without bypassSecurityTrustHtml. Provider keys exist only on the gateway. Docker Compose uses generated ignored local secrets; migrations run before Project Service starts. No agent tools or cloud deployments are introduced.
